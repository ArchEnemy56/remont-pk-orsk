# 4. ОБЯЗАТЕЛЬНОЕ РЕЗЕРВНОЕ КОПИРОВАНИЕ ПЕРЕД ИЗМЕНЕНИЕМ КОДА

Это критически важное правило. Нарушать его запрещено.

Перед каждым изменением существующего файла проекта ты обязан самостоятельно создать резервную копию.

Порядок действий:

1. Определи точный путь к файлу.
2. Создай резервную копию до любых изменений.
3. Сохрани исходную структуру директорий.
4. Используй дату и время в формате `YYYY-MM-DD_HH-mm-ss`.
5. Убедись, что резервная копия действительно создана.
6. Только после успешной проверки начинай редактирование оригинала.

### Расположение резервных копий

Предпочтительный каталог:

`remont-pk-orsk_codex_backups/`

Допустимая альтернатива:

`.codex-backups/`

Пример:

```text
remont-pk-orsk/
    AGENTS.md
    index.html
    assets/
    css/
    js/

remont-pk-orsk_codex_backups/
    2026-11-08_14-30-00/
        index.html
        css/
            main.css
        js/
            script.js
```

### Дополнительные требования

- При изменении нескольких файлов создай резервную копию каждого существующего файла.
- При повторном изменении одного и того же файла создай новую копию его текущего состояния.
- Перед удалением файла обязательно сохрани его копию.
- Не перезаписывай существующие резервные копии.
- Не удаляй старые резервные копии без разрешения пользователя.
- Не считай Git заменой резервному копированию.
- По возможности проверяй совпадение контрольных сумм оригинала и резервной копии.

Если резервную копию невозможно создать или проверить, запрещено изменять соответствующий оригинальный файл. Сначала сообщи пользователю о проблеме.

Перед запуском форматтеров, массовых замен, генераторов и других инструментов, способных изменить существующие файлы, также обеспечь резервное копирование всех затрагиваемых файлов.

Новые файлы, которых ранее не существовало, копировать перед первым созданием не требуется.

При восстановлении резервной копии сначала сохрани текущее состояние восстанавливаемого файла, чтобы откат можно было отменить.

Уточнение требуется только тогда, когда:

- Недостаточно информации для принципиально важного технического решения.

- Необходимо получить доступы, разрешения или секретные данные.

- Необратимые изменения инфраструктуры.
